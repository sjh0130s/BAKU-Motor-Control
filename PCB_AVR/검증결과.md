# 핀맵 수정 및 AVR C 변환 검증 결과

검증일: 2026-09-20. **두 결과물 모두 ATmega328P/16 MHz 대상 빌드에 성공했고, 아래 소프트웨어 시험을 통과했다. 실제 보드·CAN 버스·모터 시험은 수행하지 않았다.**

## 결과물

- `Arduino_result.zip`: 수정된 Arduino 스케치, 사용한 라이브러리 소스, 빌드 스크립트, 검증 빌드 ELF/HEX, 설명서.
- `AVR_result.zip`: Arduino 비의존 AVR C 소스, Makefile, 검증 빌드 ELF/HEX, 설명서.
- `Verification_bundle.zip`: 두 제어 소스, 자동 검증 코드, 모의 통신 계층, 빌드/시험 로그. 압축 해제 후 `verification/run_tests.sh`로 호스트 시험 재실행 가능. C/C++ 컴파일러와 AddressSanitizer/UndefinedBehaviorSanitizer 지원이 필요하다.

원본 PDF와 붙여넣은 코드는 수정하지 않았다. 문서 속 텍스트는 회로 정보로만 취급했다.

## 회로도 핀 대조

`SCH_Schematic1_2026-09-20.pdf` 1페이지를 전체 및 U1 연결부 확대 이미지로 확인했다.
아래 물리 핀 번호는 **ATmega328P-AU의 TQFP-32 패키지** 기준이다. Arduino D번호와 다르다.

| 회로 네트 | U1 포트 | U1 물리 핀 | Arduino 핀 | 소프트웨어 처리 |
|---|---|---:|---:|---|
| ETH_CS | PD7 | 11 | D7 | W5500 CS 출력, 기존 D10에서 수정 |
| CAN_CS | PB1 | 13 | D9 | MCP2515 CS 출력, 기존 값 유지 |
| CAN_INT | PD2 | 32 | D2 | 입력, CAN 수신은 폴링 |
| ETH_INT | PB0 | 12 | D8 | 입력, Ethernet 수신은 폴링 |
| SW_MANUAL | PD3 | 1 | D3 | 외부 풀업이 있는 입력 |
| SW_AUTO | PD4 | 2 | D4 | 외부 풀업이 있는 입력, 기존 SD CS 제거 |
| MOSI | PB3 | 15 | D11 | 하드웨어 SPI 출력 |
| MISO | PB4 | 16 | D12 | 하드웨어 SPI 입력 |
| SCK | PB5 | 17 | D13 | 하드웨어 SPI 출력 |
| UART_RX | PD0 | 30 | D0 | UART 수신 핀 |
| UART_TX | PD1 | 31 | D1 | UART 진단 출력 |
| 하드웨어 SS, 회로 미사용 | PB2 | 14 | D10 | SPI 마스터 유지용 HIGH 출력 |
| RESET | PC6 | 29 | 일반 D핀 아님 | W5500과 공통 RESET 네트 |

U1의 X1과 MCP2515 U4의 X2는 모두 16 MHz다. WIZ_MISO는 U6 버퍼를 거쳐 MISO로 연결된다.
버퍼의 출력 허용이 ETH_CS에 연결되어 있으므로 CS가 잘못 선택되면 공유 SPI 버스에 영향을 줄 수 있다.
수정본은 라이브러리가 개별 SPI 트랜잭션에서 CS를 제어하게 하고 외부에서 CS를 LOW로 유지하던 코드를 제거했다.

## 변경 범위

Arduino는 핀 번호 수정과 함께 `Ethernet.init(ETH_CS_PIN)`을 추가했다. 핀 상수만 바꾸면 Ethernet 라이브러리는 기본 D10을 계속 사용할 수 있기 때문이다.
SD 설정을 제거해 SW_AUTO/D4를 출력 HIGH로 구동하지 않도록 했다. 입력 핀 설정, 하드웨어 SS 출력 설정, 초기화 오류 확인, CAN 확장 데이터 프레임 검증을 추가했다.
시간 변수는 32비트로 명시했고 잘못된 500 ms 주석을 실제 1000 ms에 맞췄다.

AVR 버전은 GPIO/SPI/Timer0/UART를 레지스터로 제어하고 W5500 및 MCP2515 드라이버를 포함한다.
원본의 핵심 제어 동작과 수치 계산을 유지했다. 모드 스위치를 통한 로컬 제어는 새로 추가하지 않았다.

| 유지한 항목 | 값 / 규칙 |
|---|---|
| IP / UDP | 10.177.21.2, 포트 5000 |
| ASMS / PC | 10.177.21.5 / 10.177.21.1 |
| ASMS 데이터 | 5바이트: mode, joy_x int16 LE, joy_y int16 LE |
| PC 데이터 | 9바이트: steer int32 LE, speed int32 LE, misc |
| 모드 | 1=AUTO, 2=MANUAL, 3=ESTOP, 나머지=HALT |
| AUTO 진입 | HALT 후 새 PC 명령 대기, 같은 AUTO 모드 반복은 최신 PC 명령 유지 |
| 시간 초과 | ASMS/PC 별도 검사, 1000 ms까지 유효, 1001 ms부터 만료 |
| 주기 명령 | 핸드셰이크 성공 후 명목 50 ms 간격 |
| 조이스틱 | 데드밴드 ±120, 최대 입력 크기 2048 |
| 속도 | 최대 ±1500 RPM, AUTO 입력은 -100~100으로 제한 |
| 방향 | 원본 기준 전진=음수 RPM/전류, 후진=양수 RPM/전류 |
| 전류 기준 | 원본 PHASE_CURRENT_REF_A=500.0 A 유지 |
| CAN | 250 kbit/s, 확장 ID RX=0x1801D0EF, TX=0x0C01EFD0 |
| 핸드셰이크 | RX 첫 데이터 0x55 → 0xAA 8바이트 응답 |
| Life | uint8, 255 다음 0 |

드라이버 차이는 AVR README에 명시했다. AVR은 단일 CAN TX 버퍼에서 10 ms 제한과 전송 취소를 사용한다.
Arduino는 Seeed 라이브러리의 TX 버퍼·시간 제한을 사용한다. AVR W5500 드라이버는 소켓 0에 RX 16 KiB를 할당하며 오류 검출 시 HALT 요청 후 리셋까지 네트워크 제어를 잠근다.
정상 패킷의 제어 규칙은 유지했지만, **두 통신 드라이버의 오류 복구 방식과 시간 특성까지 동일하다고 주장하지 않는다.**

## 실제 빌드 결과

| 항목 | Arduino 수정본 | AVR C 변환본 |
|---|---:|---:|
| 대상 | arduino:avr:uno / ATmega328P | atmega328p |
| CPU | 16 MHz | 16 MHz |
| Flash | 17,198 bytes | 6,442 bytes |
| 정적 SRAM | 764 bytes | 395 bytes |
| 2,048-byte SRAM 중 잔여 | 1,284 bytes | 1,653 bytes |
| 빌드 | 성공 | 성공 |
| 자체 작성/수정 코드 경고 | 없음 | 없음, -Wall -Wextra -Werror 통과 |

정적 SRAM 값은 스택 최대 사용량을 포함하지 않는다. 실제 런타임 스택 고수위 측정은 하지 않았다.

사용 환경: Arduino CLI 1.2.0, Arduino AVR Boards 1.8.6, AVR GCC 7.3.0-atmel3.6.1-arduino7,
Ethernet 2.0.2, Seeed CAN_BUS_Shield 2.3.4 소스 스냅샷.
Arduino 빌드에는 외부 Seeed/Arduino 코어의 기존 경고가 11건 있다. 세부 내용은 `verification/arduino-build.log`에 기록했다.
라이브러리를 임의 수정하지 않았고, 패키지의 라이브러리가 실제 컴파일에 사용한 파일과 바이트 단위로 같음을 확인했다.

처음 발견한 Homebrew AVR GCC 9.5.0은 libisl 의존성 부재로 실행할 수 없어 사용하지 않았다.
대신 설치되어 있던 Arduino 배포 AVR GCC로 두 결과물을 검증했다. 부트로더 기록, 퓨즈 변경, 보드 업로드는 하지 않았다.
제공한 HEX는 애플리케이션만 포함한다.

## 자동 시험 결과

호스트 시험은 **전달한 소스 자체**를 포함/링크해 실행했다. 실제 보드의 전기적 동작을 대체하지 않는다.
제어 시험은 C++ 호스트 하네스에서 두 버전을 같은 시험 벡터로 각각 실행했다. AVR 전체는 별도로 실제 avr-gcc의 C 모드로 빌드했다.
AddressSanitizer와 UndefinedBehaviorSanitizer가 보고한 오류는 없었다.

|---|---|
| int16 조이스틱 전체 65,536개 입력, 데드밴드/방향/포화 | 두 버전 통과 |
| AUTO int32 최소·최대, ±100 경계 및 초과 입력 | 두 버전 통과 |
| 전류/속도 인코딩 및 상·하한 | 두 버전 통과 |

| MANUAL→AUTO, AUTO 반복, ESTOP, 미정의 모드 | 두 버전 통과 |

## 검증의 한계 및 보드에서 남은 확인

- 모터 프로토콜 원문은 제공되지 않았다. 전류/속도 인코딩과 500 A 기준은 원본 코드와의 일관성을 확인한 것이며, 해당 모터에 적합한 설정임을 인증한 것은 아니다.
- 실제 W5500 링크, CAN ACK, 16 MHz 클록/퓨즈, UART 파형, 모터 방향/전류, 최악 처리 지연은 계측하지 않았다.
- 회로도 R3는 CANH-CANL 사이 **82.5 kΩ**로 표기되어 있다. 이를 CAN 종단이 갖춰졌다는 근거로 보지 않았다. 외부 버스의 종단·배선 여부는 자료만으로 확정할 수 없다.
- 소프트웨어 ESTOP는 CAN HALT 명령이다. CAN이 끊겨 명령이 전달되지 않는 상황의 실제 정지는 모터 컨트롤러 측 동작과 하드웨어에 달려 있다.
- 물리 SW_MANUAL/SW_AUTO의 모드 권한과 조향/브레이크 출력은 원본에 없으므로 구현하지 않았다.

W5500 수신 헤더/포인터 처리는 [WIZnet UDP 문서](https://docs.wiznet.io/Product/Chip/Ethernet/W5500/Application/udp) 및 [데이터시트](https://docs.wiznet.io/Product/Chip/Ethernet/W5500/datasheet)를 확인했다.

SPI 하드웨어 SS 및 핀 기능은 [ATmega328P 데이터시트](https://ww1.microchip.com/downloads/en/devicedoc/atmel-7810-automotive-microcontrollers-atmega328p_datasheet.pdf)와 설치된 Arduino 표준 핀맵을 대조했다.
